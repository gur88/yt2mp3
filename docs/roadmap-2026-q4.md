# AudioGrab — план роста, Q4 2026

**Горизонт:** сентябрь – декабрь 2026, ~12 недель.
**Проект запущен:** 19 июля 2026 (на момент плана — ~7 недель).

## Цель фазы

Не выручка. Довести проект до состояния, где решение «монетизировать
рынок СНГ или нет» принимается по данным, а не на ощупь.

Причина: продукту 7 недель, весь обнаруженный спрос — «достать аудио из
видео ВК» (89% кликов в GSC), 100% трафика — Россия, зарубежных кликов за
3 месяца ноль. Идти на западный рынок сейчас — значит одновременно решать
три нерешённые задачи (привлечение в худшей SEO-нише, платёжные рельсы,
которых нет у резидента РФ без выезда, отстройка продукта). Сначала —
доказать экономику там, где это дёшево проверить.

## Что НЕ делаем в этой фазе

- Платёжную интеграцию.
- Английский / западный контент.
- Новые источники вне СНГ-набора (Instagram, Spotify и т.п.).
- Редизайн.
- API, десктоп-приложение.

### Установка дайджеста на боксе (разово, по SSH root)

```sh
sudo grep -E 'BOT_TOKEN|CHAT_ID' /etc/yt2mp3-alerts.env   # взять значения

sudo tee /etc/yt2mp3-digest.env >/dev/null <<'EOF'
UMAMI_USERNAME=admin
UMAMI_PASSWORD=<пароль от analytics.audiograb.ru>
UMAMI_URL=http://127.0.0.1:3001
UMAMI_WEBSITE=19460776-616d-4b04-888d-509b1d7ebba3
BOT_TOKEN=<из yt2mp3-alerts.env>
CHAT_ID=<из yt2mp3-alerts.env>
EOF
sudo chown yt2mp3:yt2mp3 /etc/yt2mp3-digest.env && sudo chmod 600 /etc/yt2mp3-digest.env

sudo cp /var/www/yt2mp3/ops/systemd/umami-digest.service /etc/systemd/system/
sudo cp /var/www/yt2mp3/ops/systemd/umami-digest.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now umami-digest.timer

sudo systemctl start umami-digest.service   # проверить: должно прийти в Telegram
journalctl -u umami-digest.service -n 20 --no-pager
```

## Трек 3 — Контент и SEO (недели 2–10, основная работа)

### Карта запросов (сначала)

По каждому источнику head + длинный хвост (сид из GSC + Wordstat),
сгруппировать по интенту:

- **ВК:** «скачать музыку из вк видео», «вк видео в мп3», «скачать звук
  с клипа вк», «скачать аудио вк по ссылке», мобильные, «как скачать…».
- **ВК Клипы:** «скачать клип вк без водяного знака» — отдельный интент.
- **ОК:** аналогичный набор.
- **RuTube:** «скачать музыку с rutube», «rutube в mp3».
- **YouTube (для РФ актуален):** «ютуб в мп3», «скачать музыку с ютуба»,
  «скачать обложку с видео ютуб» (по обложке уже есть показы).
- **Подкасты / лекции:** «скачать подкаст», «скачать лекцию с ютуба».
- **Яндекс.Музыка — сначала проверить, что yt-dlp это тянет** (юридически
  и технически мутно). Если нет — страницу не делать.

### Архитектура страниц — по порядку приоритета

Данные среза: используются только VK (72% скачиваний) и YouTube (28%),
причём YouTube-трафик садится на главную. Отсюда очередь:

1. **Добить `/vk` с позиции 8 в топ-3** — доказанный лидер, 89% поисковых
   кликов. Расширить текст, FAQ, 2–3 бэклинка (Ответы Mail.ru, Яндекс.Кью,
   тематические группы/форумы), улучшить title/description под CTR,
   проверить скорость.
2. **Сделать нормальный лендинг `/youtube`** под RU-запросы («ютуб в мп3»,
   «скачать музыку с ютуба») — сейчас этот трафик идёт на `/` и там же
   фейлится на превью. Увести его на выделенную страницу.
3. **`/ok`, `/rutube`, `/vk/klip`** — только после того, как первые два
   дадут рост. Не распыляться заранее.

Есть `/vk`, `/tiktok`, `/soundcloud`, `/thumbnail`. Каждая страница:

- серверный H1 + вводный текст под кластер (200–400 слов полезных),
- рабочий инструмент на странице,
- FAQ-блок с FAQPage-разметкой,
- перелинковка на другие источники.

### Статьи под длинный хвост

1–2 в неделю, каждая под «как скачать X» с низкой конкуренцией,
с перелинковкой на лендинги.

### Тех-SEO база

Уникальные title+meta на страницу, canonical, OG, быстрый TTFB, sitemap
автообновляемый, breadcrumb-разметка.

### Бэклинки (фоном, низкая интенсивность)

Каталоги (startpack, AlternativeTo), профильные форумы, Q&A-сайты,
попадание в подборки «сервисы скачать музыку с вк».

**Готово, когда:** 6–8 крепких лендингов, ~15–20 howto-статей, `/vk`
в топ-3, клики в GSC идут к 60–100/день, кликают несколько страниц.

## Трек 4 — Надёжность (недели 2–10, параллельно, ~1–2 дня/нед)

Единственный устойчивый ров. Упавший конвертер неотличим от скам-сайта.

- [ ] **Приоритет — `preview_error`, не загрузка.** 19% (VK) / 23% (YouTube)
      вставленных ссылок отваливаются на превью — до скачивания, самый
      дешёвый по трудозатратам этап. После фикса `reason` (Трек 1) разобрать
      топ причин по VK и YouTube.
- **ВК** — основной источник (72% скачиваний), фейл превью ~19%, фейл
  загрузки ~7%. Проверенный пин yt-dlp, дашборд ошибок, реактивная
  дисциплина обновлений (`deployment.md`). Разобрать повторяющиеся краши
  экстрактора. Проверить, стабилизируют ли VK-cookie (риск: протухание, ToS).
- **YouTube** — второй по факту (28%), фейл превью ~23%, фейл загрузки ~13%
  (хуже VK на обоих этапах). Разобрать вместе с `/youtube`-лендингом
  (Трек 3). Риск anti-bot по датацентр-IP — план (cookies/прокси) держать
  наготове.
- **TikTok / SoundCloud / thumbnail** — скачиваний ноль. Не вкладываться:
  ни в контент, ни в прокси, ни в отладку. TikTok при желании пометить
  в UI как нестабильный.
- [ ] Retry-once: на транзиентной ошибке экстрактора один авто-ретрай
      на сервере до показа ошибки.
- [ ] Синтетический мониторинг: к `ops/healthcheck.sh` + часовому GitHub
      Action добавить — раз в час реально качать фиксированный URL по
      каждому источнику, писать успех/провал, алерт в Telegram при
      устойчивом падении источника.
- [ ] Регресс-гейт перед бампом yt-dlp: формализовать таблицу ручных
      тестов из `deployment.md`, прогонять на каждый бамп.

**Готово, когда:** success rate по источникам на графике, часовой
синтетик-чек работает, ВК заметно лучше или сознательно принят как есть,
retry-once на месте.

## Гейт решения (недели 11–12)

Смотрим: клики/день, % возвратов, success rate по источникам, какие
страницы ранжируются. Выбор:

1. **Монетизировать СНГ** — если есть рост трафика и понятный платящий
   сценарий. Дальше — отдельный план (free + лимиты + реклама, дешёвый
   Pro через ЮKassa / Telegram Payments / Boosty, lifetime + месячный
   доступ).
2. **Продолжать растить** — если трафик растёт, но рано.
3. **Проект на рекламе / в портфолио** — если даже ежедневные
   пользователи платить не готовы. Тогда «попробовать Запад» — не вывод;
   на Западе при тех же вводных легче не станет.
